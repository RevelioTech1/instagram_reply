# Иордань — ответы на комментарии Instagram

Панель для мастерской [Иордань](https://iordani.com). Она читает комментарии под постами Instagram и готовит ответ: цену, размер, наличие, доставку или ссылку на карточку товара. Цена берётся только из карточки на сайте. Если изделие неясно, панель не выбирает его наугад и просит артикул.

Автоответ по умолчанию выключен. В Instagram ничего не уходит, пока человек в панели не нажмёт «Отправить в Instagram» или не включит автоответ.

## Что умеет

- Находит изделие по артикулу в подписи поста или в комментарии. `Б-КО-338`, `B-KO-338` и запись без дефисов ведут в одну карточку.
- Если в кадре несколько изделий, смотрит слова комментария: «а серёжки почём?» не получит цену кольца.
- Общие названия вроде «Спаси и Сохрани» не схлопывает в одну цену. В таком случае просит артикул.
- Считает вопросом о цене и отдельные теги: `+`, `++`, `хочу`, `хочу такое`, `беру`, `куплю`, `закажу`. Список правится в «Подключении».
- На комплимент вроде «Какая красота» или «Супер украшения» отвечает короткой благодарностью, без цены и без ссылки.
- Публичный ответ пишет под комментарием. Ссылку на карточку отправляет одним личным сообщением: в комментарии она часто не нажимается. На один комментарий — одно сообщение.
- Сомнительный вопрос, например про крещение, оставляет человеку. В ответе телефон мастерской, без выдуманной цены.
- Каталог сам подтягивается с сайта примерно раз в час. Кнопка в «Подключении» запускает внеочередное обновление. Старые цены остаются, пока загрузка не закончится успешно.

В подпись поста лучше сразу ставить артикул. Тогда ответ почти всегда попадает в нужную карточку.

## Что поставить на компьютер

Нужны Git и Node.js **22 или новее**. Проверка:

```bash
node -v
npm -v
```

Если версия Node меньше 22, скачайте актуальную с [nodejs.org](https://nodejs.org/). Отдельная база, Docker и файл с паролями не нужны.

## Установка в новый репозиторий

На машине клиента:

```bash
git clone <адрес-репозитория>.git
cd <имя-папки>
cp .env.example .env
# Задайте PANEL_PASSWORD в .env — без него панель не откроется.
npm install
npm run dev
```

Панель откроется на [http://localhost:4317](http://localhost:4317). Браузер спросит логин и пароль из `.env` (`PANEL_USER` / `PANEL_PASSWORD`).

При первом запуске сама создаётся база `data/concierge.sqlite`. Снимок каталога уже лежит в `data/catalog.json`, сайт для старта читать не нужно.

Остановить панель: в том же окне терминала нажмите `Ctrl+C`.

### Если репозиторий ещё пустой

На компьютере, где уже есть эта папка с кодом:

```bash
cd <папка-с-кодом>
git init
git add .
git commit -m "Панель ответов на комментарии Иордань"
git branch -M main
git remote add origin <адрес-нового-репозитория>.git
git push -u origin main
```

Дальше клиент делает `git clone`, как в блоке выше. Файл базы в репозиторий не попадёт: он указан в `.gitignore`. Токен Instagram тоже хранится только в этой базе, на компьютере, где запущена панель.

## Разделы панели

- **Входящие.** Список комментариев и текст ответа. Можно поправить фразу и отправить, пропустить или привязать артикул вручную.
- **Посты.** Публикации, под которыми уже есть разобранные комментарии. Пост без артикула можно закрепить за одним изделием.
- **Каталог.** Карточки с сайта: артикул, цена, металл, размер. Отсюда же запускается обновление.
- **Подключение.** Вход в Instagram, автоответ, теги цены, шаблоны на реакции, телефон в ответах про доставку.

Кнопка «Неотвеченные из 20 последних постов» читает 20 свежих публикаций и комментарии под ними. В панель попадают комментарии без публичного ответа от аккаунта магазина; уже отвеченные магазином остаются во входящих со статусом «Ответили». Полный обход ленты отключён из‑за лимитов Instagram. Свои комментарии пропускаются. Уже лежащие во входящих второй раз не добавляются. Пока автоответ выключен, новые вопросы остаются черновиками.

## Как включается Instagram

Аккаунт должен быть профессиональным (бизнес или автор). Публичная страница Facebook для входа не нужна.

Meta не сохраняет адрес `http://localhost`. Панель на время входа нужно открыть по публичному `https`-адресу. Пока нет своего домена, подойдёт туннель на порт `4317`, например Cloudflare Tunnel:

```bash
cloudflared tunnel --url http://localhost:4317
```

Дальше панель открывают по выданному адресу `https://….trycloudflare.com`, не по localhost.

1. Откройте [список приложений Meta](https://developers.facebook.com/apps/) и нажмите «Создать приложение». Страница «Платформа Instagram» в меню продуктов приложение не создаёт.
2. В сценариях выберите «Manage messaging & content on Instagram». Имя приложения не должно содержать слов Insta, Gram и IG.
3. Внутри приложения откройте Instagram → «API setup with Instagram business login». Скопируйте оттуда Instagram App ID и Instagram App Secret. Это не номер из «Настройки → Основные».
4. Вставьте их в панели, раздел «Подключение».
5. Адрес возврата из панели вставьте в шаг **«4. Настройте вход в Instagram от имени компании»**. Поле «URL обратного вызова» в шаге про Webhooks — другое, его пока не заполняйте. Адрес должен совпасть символ в символ, без слэша на конце: `https://<ваш-адрес>/api/instagram/callback`.
6. Пока приложение не опубликовано, откройте вкладку «Роли», в блоке Instagram Testers добавьте имя аккаунта и примите приглашение на [instagram.com/accounts/manage_access](https://www.instagram.com/accounts/manage_access/). Роль администратора Facebook этот шаг не заменяет.
7. В панели нажмите «Войти через Instagram» и войдите именно в тот аккаунт, который принял приглашение.

Сессия живёт около 60 дней и продлевается сама. Кнопка «Выйти» отключает аккаунт в панели.

Пока приложение Meta в режиме разработки, интерфейс отдаёт только комментарии людей, добавленных в роли. Комментарии остальных подписчиков скрыты, даже если счётчик на посте их показывает. Чтобы читать всех, заявку на права отправляют в App Review и публикуют приложение. Для этой панели нужны три права: `instagram_business_basic`, `instagram_business_manage_comments`, `instagram_business_manage_messages`. Право на публикацию постов не нужно.

Чтобы новые комментарии приходили сами, без кнопки, в Meta указывают вебхук:

- адрес: `https://<ваш-адрес>/api/instagram/webhook`
- поле: `comments`
- проверочный токен показан в панели, в блоке «Вебхук Meta»

Секрет приложения Meta для подписи вебхука обязателен: без него `POST` на вебхук отклоняется. Его вставляют в «Токен вручную».

Готовый токен Страницы Facebook, если он уже есть, тоже вставляется в «Токен вручную». Обычный путь — кнопка «Войти через Instagram».

## Постоянная работа

На сервере, где панель должна работать сама:

```bash
cp .env.example .env   # если ещё нет; задайте PANEL_PASSWORD
npm install
npm run build
npm run start
```

Панель слушает порт `4317` на всех сетевых интерфейсах. Вход в панель и во все API, кроме вебхука Meta и `/api/health`, закрыт встроенным Basic Auth (`PANEL_USER` / `PANEL_PASSWORD`). Процесс нужно держать запущенным: через службу systemd, pm2 или аналог. Для входа Instagram перед панелью должен быть постоянный `https`-адрес, и в Meta должен быть записан именно он.

Обновление кода:

```bash
git pull
npm install
npm run build
npm run start
```

База `data/concierge.sqlite` при этом остаётся на месте. Её не удаляют: там токен, правила и разобранные комментарии.

Автообновление каталога включается вместе с процессом Node. Интервал задаётся `CATALOG_SYNC_INTERVAL_MS` (по умолчанию час). Выключить: `CATALOG_SYNC_ENABLED=0`. Если с сайта пришло слишком мало карточек, снимок не заменяется.

## Проверка

```bash
npm test
```

Проверяется разбор цены, артикула, знака «+», тега «хочу», комплимента и отказа выдумывать цену.

## Чего не класть в git

- `data/concierge.sqlite` и соседние файлы базы. Там токен Instagram.
- `node_modules` и `.next`. Они собираются заново командами выше.
